# 自動実行設計

Version: 2.0.0

---

# 1. 実行場所

すべて GitHub のクラウド（ubuntu-latest）。データ元（Boatrace Open API）は GitHub Pages なので
クラウドから取得できる。GITHUB_TOKEN による push は他のワークフローを起動しないため、
後続処理は同じワークフローの後続ジョブとして呼ぶ。

# 2. 分析（.github/workflows/20_analyze.yml）

* `data/input/**`・`scripts/br/analysis/**` への push、収集・取り込みの後続、手動実行で動く。
* テスト → 検証（04_02）→ data/output/ を commit → ダッシュボード公開（21_pages.yml）。

# 3. 収集（10_collect.yml）

毎朝6:00（JST）に直近7日分を取得して push し、後続で分析する（02_01 4章）。

# 4. 当日予想（11_predict.yml）

GitHub の定期実行は混雑時に遅れたり間引かれたりする（10分ごとの指定で1日2回しか動かなかった実績あり）。
そのため1回の実行の中で5分ごとに予想を繰り返す（最長5時間40分、7:45〜21:30 JST の間だけ）。
定期起動は8:00〜21:59（JST）の30分ごとで、同時に動くのは1つだけ（concurrency）。
締切が近く直前情報がそろったレースを予想して push し（04_01 6章）、予想が増えたときだけ
21_pages を workflow_dispatch で起動してダッシュボードを公開する。

# 5. 過去データの取り込み（12_backfill.yml）

`.github/backfill.json`（`{"from": "YYYY-MM-DD", "to": "YYYY-MM-DD"}`）を push すると始まる。
1か月ごとに push し、取得済みの日は飛ばす。終わったら分析する。

# 6. ダッシュボード公開（21_pages.yml）

ダッシュボード（06_02）を生成し、GitHub Pages（Source: GitHub Actions）に公開する。
