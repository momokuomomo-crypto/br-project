# 自動実行設計

Version: 1.0.0

---

# 1. 実行場所

| 処理 | 実行場所 | 理由 |
|---|---|---|
| 収集・当日予想 | 自前の実行マシン（利用者のPC、ラベル `self-hosted, jp`、Windows） | 公式サイトが海外からのアクセスを拒否するため |
| 分析・ダッシュボード | GitHub のクラウド（ubuntu-latest） | 公式サイトにアクセスしないため |

GITHUB_TOKEN による push は他のワークフローを起動しないため、収集・予想の後続処理は
同じワークフローの後続ジョブとして呼ぶ。

---

# 2. 分析（.github/workflows/20_analyze.yml）

* `data/input/**` への push、収集ワークフローの後続、手動実行で動く。
* テスト → 検証（04_02）→ data/output/ を commit → ダッシュボード公開（21_pages.yml）。

# 3. 収集（10_collect.yml）

* 毎朝5:30（JST）：直近7日分（取りこぼし分を含む）を収集して push（02_01 5章）。
* 手動実行（開始日・終了日・オッズの有無・最大実行時間）：過去データの取り込み（02_01 6章）。
  1か月ごとに push する。
* 後続で分析（2章）を行う。

# 4. 当日予想（11_predict.yml）

* 8:00〜21:59（JST）の15分ごと：締切が近いレースを予想して push（04_01 6章）。
* 予想が増えたときだけダッシュボードを公開する。
* 実行マシンは1台で1件ずつ処理するため、過去データの取り込み中は予想が待たされる。

# 5. ダッシュボード公開（21_pages.yml）

ダッシュボード（06_02）を生成し、GitHub Pages（Source: GitHub Actions）に公開する。

# 6. 実行マシンの登録

利用者のPCに GitHub Actions Runner を `C:\br-runner` に置き、ログオン時に自動起動する。
PCが止まっている間は収集・予想が行われない。
