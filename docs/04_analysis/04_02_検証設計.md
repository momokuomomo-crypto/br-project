# 検証設計

Version: 1.0.0

---

# 1. 目的

期待値派の成績を、学習にもルール選びにも使っていない期間で正直に測る。

実装：`scripts/br/analysis/backtest.py`

```text
python -m br.main backtest [--valid-start YYYYMMDD --test-start YYYYMMDD]
```

---

# 2. 期間

データの最新日から数えて

| 期間 | 既定 | 用途 |
|---|---|---|
| 学習 | 選定期間より前のすべて | モデルの学習 |
| 選定 | 確認期間の前の6か月 | 購入ルールの選択 |
| 確認 | 最後の6か月 | 成績の確認（何の決定にも使わない） |

---

# 3. 手順

1. 学習期間だけでモデルを学習する。
2. 選定期間で、購入ルールの候補を試す。

   | 券種 | EV 基準 | オッズ上限 |
   |---|---|---|
   | 単勝 | 1.0・1.1・1.2・1.3・1.5 | 10・30・100倍 |
   | 2連単 | 同上 | 30・100・300倍 |
   | 3連単 | 同上 | 100・300・1000倍 |

   購入点数が300点以上の候補のうち、回収率が最も高いものを選ぶ。
3. 学習＋選定期間でモデルを学習し直し、2. のルールで確認期間を評価する。
4. 参考として、同じルールを市場の見立てのまま（補正なし）使った場合の成績も出す。
5. 運用用に、全期間でモデルを学習し直して data/output/model.json に保存する
   （ルールは 2. のもの）。

---

# 4. 出力

* backtest_report.json：期間・係数・対数損失（市場の見立てとモデル）・全候補の成績・
  選んだルール・確認期間の成績
* backtest_ledger.csv：確認期間に買った買い目と払戻

---

# 5. 注意

* 検証は確定オッズで計算する。実際に買う時点のオッズは締切直前まで動くため、
  確認期間の成績は実際より良く見えることがある。実際に近い成績は、
  当日予想の記録（04_01 6章）で継続して確認する。
* 候補を多く試すほど、選定期間の成績は偶然良く見える。だから確認期間で確かめる。
* データが増えたら同じ手順で選び直す（自動実行のたびに再計算する）。
